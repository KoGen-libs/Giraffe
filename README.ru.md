# Giraffe: Руководство пользователя

**Giraffe** — это библиотека для Android, которая перехватывает gRPC-трафик и показывает его прямо в приложении, в виде удобного просмотрщика — без прокси, без десктопных инструментов, работает прямо на том устройстве, где запущено приложение.

[Read in English](README.md)

**Основные принципы:**
* **Ноль настройки:** Достаточно добавить зависимость — никакого KSP-плагина, аннотаций и настройки на вашей стороне.
* **Всё на устройстве:** Трафик пишется в локальную, приватную базу данных Room — ничего не уходит с телефона.
* **Понимает содержимое:** Изображения, аудио, видео и произвольные бинарные данные распознаются и извлекаются, даже если они спрятаны внутри protobuf-сообщения, которое в остальном выглядит как текст/JSON.

## 🚀 Установка и настройка

### Шаг 1: Добавляем зависимость

Библиотека опубликована в **Maven Central** в виде единого, самодостаточного AAR.

```kotlin
dependencies {
    // Актуальную версию смотрите в бейдже выше
    debugImplementation("io.github.eugenprog:giraffe:<version>")
    releaseImplementation("io.github.eugenprog:giraffe-no-op:<version>")
}
```
Внутри Giraffe использует KSP для сборки своего собственного UI, но это уже запечено в опубликованный артефакт — вам не нужно подключать плагин KSP или что-либо настраивать, чтобы просто подключить библиотеку.

`giraffe-no-op` — отдельный артефакт с тем же самым классом `GiraffeInterceptor` и тем же конструктором, но `interceptCall` в нём просто пробрасывает вызов дальше в канал — без логирования, без базы, без уведомлений. Подключение через `releaseImplementation` даёт то, что строчка, подключающая интерсептор (см. ниже), компилируется без изменений и в debug, и в release — а в release-сборку настоящие зависимости Giraffe (Room, Compose, media3, Coil) вообще не попадают, не просто не работают в runtime, а физически отсутствуют в APK. Если у вас один build type на всё — просто подключите `io.github.eugenprog:giraffe` напрямую через `implementation` и сами оберните вызов `GiraffeInterceptor(...)` (см. **Важные заметки** ниже).

### Шаг 2: Разрешение на уведомления (Android 13+)

Giraffe присылает системное уведомление на каждый перехваченный вызов, чтобы можно было сразу в него провалиться. Начиная с API 33, для этого нужно runtime-разрешение `POST_NOTIFICATIONS` — Giraffe объявляет его в своём манифесте, но запросить его во время выполнения должно ваше приложение, точно так же, как для любого другого уведомления:
```kotlin
if (ContextCompat.checkSelfPermission(this, Manifest.permission.POST_NOTIFICATIONS)
    != PackageManager.PERMISSION_GRANTED
) {
    ActivityCompat.requestPermissions(this, arrayOf(Manifest.permission.POST_NOTIFICATIONS), REQUEST_CODE)
}
```
Без него трафик всё равно логируется и доступен в приложении — просто уведомлений о нём не будет.

## ⚙️ Как пользоваться

### 1. Подключаем интерсептор

Добавьте `GiraffeInterceptor` к gRPC-каналу, который хотите отслеживать:
```kotlin
val channel = AndroidChannelBuilder
    .forAddress(host, port)
    .context(context)
    .usePlaintext()
    .intercept(GiraffeInterceptor(context.applicationContext))
    .build()
```
Каждый запрос и ответ на этом канале теперь логируется — по возможности разобранный по полям — и на него отправляется уведомление о трафике.

### 2. Открываем просмотрщик

Тапните по уведомлению о трафике (или сами запустите `GiraffeActivity`, например из debug-меню), чтобы открыть собственный экран Giraffe: список вызовов и экран деталей по каждому — с полной историей запросов/ответов.

* Тап по бабблу с **картинкой** или **видео** открывает полноэкранный просмотр — с пинч-зумом для картинок и автостартом для видео — плюс кнопка "поделиться".
* Маленькая иконка **копирования** под каждым сообщением копирует текст именно этого сообщения.
* Иконка **копирования** в шапке экрана деталей копирует **весь** вызов целиком как текст — URL, заголовки и все тела запросов/ответов подряд в том порядке, в котором они шли — готово для вставки в баг-репорт. Содержимое файлов туда никогда не попадает.
* Выделите чаты в списке, чтобы удалить их — закэшированные медиафайлы удаляются вместе с ними.

## ✨ Возможности

* Распознаёт изображения, аудио, видео и произвольные бинарные данные, даже если они спрятаны внутри protobuf-сообщения, которое в остальном выглядит как JSON — и заменяет именно этот вложенный кусок на плейсхолдер, оставляя остальное сообщение читаемым.
* Хранит всё в локальной базе Room, так что лог переживает переход между экранами, смерть процесса и перезапуск приложения.
* Поставляется с собственным UI на Jetpack Compose (на основе MVI) — самим ничего строить не нужно.

## ⚠️ Важные заметки

1. **Это инструмент для отладки.** Не оставляйте его подключённым в проде. Предпочтительный способ: `debugImplementation` на реальный артефакт и `releaseImplementation` на `giraffe-no-op` (см. **Установку**) — без условного кода, и реальные зависимости вообще не попадают в релиз. Если вы не используете build-type-специфичные зависимости — оберните вызов `GiraffeInterceptor(...)` в `BuildConfig.DEBUG` сами, но учтите: это только останавливает его *выполнение*, зависимости реального артефакта всё равно попадут в релизный APK.
2. **`loggingEnabled = false`** у `GiraffeInterceptor` отключает только вывод в `Log.d` — трафик всё равно пишется в базу и уведомления всё равно приходят, независимо от этого флага.
3. **Медиафайлы** пишутся в приватную кэш-директорию приложения и раздаются наружу (с экранов превью) через собственный `FileProvider` библиотеки — объявлять свой не нужно.
